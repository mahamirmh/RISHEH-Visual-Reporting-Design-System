# راهنمای تصویری RISHEH Visual Reporting Design System

> دوره کاربردی از مفاهیم پایه تا ساخت گزارش. تمامی اعداد مثال‌ها فرضی‌اند.

![نقشه مسیر یادگیری](../assets/learning-path.svg)

## فصل ۱ — تفاوت اصطلاحات

| مفهوم | پاسخ به چه پرسشی؟ | مثال |
|---|---|---|
| Brief | چرا و برای چه کسی؟ | هدف گزارش ماهانه مدیرعامل |
| Blueprint | اجزا چگونه به هم متصل‌اند؟ | ورودی → اعتبارسنجی → خروجی |
| Chart | اعداد چه الگویی دارند؟ | روند فروش در ۱۲ ماه |
| Diagram | روابط چگونه‌اند؟ | ارتباط ماژول‌های یک پلتفرم |
| Flowchart | مرحله بعد چیست؟ | مسیر تأیید درخواست |
| Wireframe | عناصر کجای صفحه‌اند؟ | اسکلت داشبورد |
| Dashboard | اکنون چه وضعیتی داریم؟ | KPIها و هشدارها |

![تفاوت نمودار و فرایند](../assets/visual-vocabulary.svg)

### تمرین
یک گزارش ساده را در نظر بگیر: «تعداد درخواست‌ها در هر ماه». اگر سؤال «چقدر تغییر کرده؟» باشد Line Chart مناسب است. اگر «کدام ماه بیشتر است؟» باشد Bar Chart مناسب است. اگر «چطور درخواست ثبت می‌شود؟» باشد Flowchart مناسب است.

## فصل ۲ — قواعد انتخاب تصویر

![درخت تصمیم نمایش](../assets/visual-decision-tree.svg)

1. آیا داده کمی و دارای محور زمان است؟ **Line**.
2. آیا مقایسه دسته‌هاست؟ **Bar**.
3. آیا مقدار دقیق هر ردیف مهم است؟ **Table**.
4. آیا توالی مراحل مهم است؟ **Timeline / Flow**.
5. آیا یک مقدار اصلی وجود دارد؟ **Metric Card**.
6. آیا هدف، توضیح مفهوم است؟ **Diagram / Callout**.

**اشتباه رایج:** استفاده از نمودار دایره‌ای برای داده‌های منفی یا داده‌هایی که بخش‌های یک کل نیستند.

## فصل ۳ — از داده تا گزارش

![معماری گزارش](../assets/architecture.svg)

### گام ۱: داده ورودی

```json
{"month":"فروردین","requests":24}
```

این داده **نمونه ساختگی آموزشی** است.

### گام ۲: انتخاب مدل میانی

فایل [نمونه کامل](../examples/sample-report.json) را باز کن. ساختار شامل `schemaVersion`، `id`، `locale`، `sources` و `blocks` است.

### گام ۳: اعتبارسنجی

```ts
import { validateReport } from "../src/core.js";
const errors = validateReport(report);
if (errors.length) throw new Error(JSON.stringify(errors));
```

### گام ۴: نمایش

```tsx
import { ReportView } from "../src/react.js";
<ReportView report={report} />
```

### گام ۵: خروجی سند

```ts
import { toDocx, toPdf } from "../src/export.js";
const wordBytes = await toDocx(report);
const pdfBytes = await toPdf(report);
```

**محدودیت:** تا زمان تأیید فونت و شکل‌دهی حروف، خروجی PDF فارسی را برای انتشار نهایی استفاده نکن.

## فصل ۴ — اصول چیدمان

- ابتدا عنوان و خلاصه، سپس شاخص‌ها، بعد شواهد و جزئیات.
- هر نمودار عنوان، واحد، بازه و توضیح دسترس‌پذیر داشته باشد.
- روی موبایل جدول افقی قابل پیمایش باشد؛ محتوا حذف نشود.
- جهت RTL برای فارسی تنظیم شود، اما داده‌های فنی و URLها جهت منطقی خود را حفظ کنند.
- از رنگ به‌عنوان تنها نشانه وضعیت استفاده نکن.
- از دست‌نوشته و حاشیه‌نویسی تزئینی استفاده نکن؛ تایپوگرافی باید حرفه‌ای و خوانا باشد.

## فصل ۵ — تمرین نهایی

یک گزارش آزمایشی با سه Block بساز: `metric`، `bar` و `flow`. عنوان، داده، منابع و متن جایگزین را اضافه کن. با `npm run check` اعتبارسنجی کن. سپس خروجی وب و اسناد را از نظر چیدمان و صحت داده مقایسه کن.
