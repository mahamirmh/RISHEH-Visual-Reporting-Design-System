# راهنمای کنترل کیفیت و تحویل گزارش بصری

## سه سطح کیفیت را اشتباه نگیریم

**Code Review:** کد از نظر ساختار و منطق بررسی شده است. **Automated Test:** برنامه واقعاً اجرا و با انتظار مقایسه شده است. **Visual QA:** خروجی روی صفحه یا سند دیده و ارزیابی شده است. گذر از یک سطح جای دو سطح دیگر را نمی‌گیرد.

## چک‌لیست محتوایی
- عنوان گزارش سؤال مخاطب را روشن می‌کند.
- هر عدد واحد، بازه زمانی و در صورت نیاز منبع دارد.
- داده‌های نمونه با برچسب «ساختگی» مشخص‌اند.
- عنوان و توضیح نمودار با اعداد سازگارند.
- جدول جایگزین نمودار اطلاعات اصلی را حفظ می‌کند.

## چک‌لیست رابط
- فارسی راست‌به‌چپ و متن لاتین خواناست.
- در عرض موبایل اسکرول افقی ناخواسته وجود ندارد.
- کنتراست و فوکوس صفحه‌کلید قابل تشخیص است.
- معنا فقط از طریق رنگ منتقل نشده است.
- محتوای طولانی و جدول‌ها بریده نمی‌شوند.

## چک‌لیست سند
- PDF فارسی: اتصال حروف، علائم، اعداد، سطرها و شکست صفحات.
- DOCX: راست‌چین بودن، جدول‌های بلند، کیفیت تصویر و سازگاری با Word.
- نمودار: تناسب تصویر و عدم بریدگی برچسب‌ها.
- لینک‌ها و منابع: صحیح و قابل پیگیری.

## دستورهای اجرای تست
```bash
npm install
npm run check
npm run build
npx playwright install chromium
npm run test:e2e
npm audit --omit=dev
```
تا وقتی `package-lock.json` در مخزن ثبت نشده، از `npm ci` به‌عنوان دستور قطعی استفاده نکن.
